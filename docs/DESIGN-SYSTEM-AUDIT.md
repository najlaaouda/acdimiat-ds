### 0.4 ما استُبعد من التحليل

### 0.5 ملاحظة معمارية جوهرية

**لا يوجد أي عزل CSS بين الـ Admin والموقع العام.**

`admin.component.scss` فارغ، و`angular.json` يحمّل كل الملفات العامة على كل المسارات. الفصل بين "نظامَي التصميم" قائم فقط على *أي كلاسات تصادف أن يستخدمها كل قالب* — لا على أي آلية theming (لا `body.admin-*`، لا `:host-context`، لا stylesheet لكل وحدة).

**التبعة:** أي تعديل في `panel-style.css` يصيب الطرفين معًا. هذا يقيّد كل استراتيجية الترحيل ويجعل الخطوة صفر (نطاق `.ap-admin`) شرطًا لكل ما بعدها.

**فارق ثانٍ مهم:** الموقع العام **قابل للتخصيص لكل أكاديمية** (tenant theming)، بينما الـ Admin ذو هوية ثابتة. أي نظام tokens يجب أن يحترم هذا الفرق البنيوي.

الألوان ليست عشوائية. التحليل يكشف **ثلاث طبقات زمنية** واضحة، كل واحدة تخصّ وحدات بعينها:

### 1.6 ألوان مُعلَنة لا يقرؤها أحد (Orphaned tokens)

معرّفة في `:root` داخل `panel-style.css` ولا يستهلكها أي قالب حقيقي:

| Token | القيمة | الحالة |
|---|---|---|
| `--primary` | `#eb8153` (برتقالي) | 💀 ميت — ومُعلن **مرتين** في نفس الملف (سطر 19 و 2342) |
| `--secondary` | `#6418c3` | 💀 ميت كمتغيّر (لكن `.btn-secondary` يكتب `#6418c3` حرفيًا) |
| `--bs-primary` / `--bs-success` / `--bs-danger` / `--bs-secondary` | `#309255` / `#309255` / `#dc3545` / `#e7f8ee` | 💀 مُعلنة — بينما `.btn-primary`/`.btn-success`/… تكتب قيمها الحرفية بدلًا من قراءتها |
| `--panel-color-primary-*` | أخضر | 💀 ميت |
| `$acadimiat-primary` (Material) | `indigo` | 💀 يُلوّن مكوّنات `mat-*` فقط، ومنفصل بصريًا عن كل أزرار التطبيق الحقيقية |
| `--font-family-main` | `'Readex Pro'` | مُعلن **مرتين متتاليتين** في نفس البلوك (سطر 65 و 67) |

**الدرس المنهجي:** وجود متغيّر ≠ وجود مستهلك له. عند بناء النظام الجديد يجب التحقق من *الاستهلاك* لا من *الإعلان*.

### 1.7 النموذج الإيجابي المضاد — مجموعة `--tk-*`

وحدة `tickets` بنَت **مجموعة tokens دلالية كاملة وصحيحة البنية** داخل `:host`:

```scss
--tk-bg / --tk-bg-subtle / --tk-bg-muted / --tk-bg-hover
--tk-border / --tk-border-subtle / --tk-border-focus
--tk-text / --tk-text-secondary / --tk-text-muted
--tk-success / --tk-success-bg / --tk-success-border
--tk-danger  / --tk-danger-bg  / --tk-danger-border
--tk-warning / --tk-link / --tk-shadow / --tk-shadow-sm / --tk-overlay
```

**هذه هي البنية الصحيحة بالضبط** — لكنها مكرَّرة نصًّا في **5 ملفات**، محبوسة في وحدة واحدة، وأسماؤها محلية. النظام الجديد يجب أن **يعمّم هذا النمط حرفيًا** تحت بادئة `--ap-*`.

## 2. Typography

### 2.1 الخط

`Readex Pro` مفروضة عبر محدّد شامل في `styles.scss`:

```scss
* { font-family: "Readex Pro", sans-serif; }
```

محمّلة من Google Fonts بالأوزان: **300, 400, 500, 600, 700**.

### 2.2 🔴 مشكلة حرجة — أوزان غير محمّلة (146 استخدامًا)

| الوزن | استخدامات في Admin | محمّل؟ |
|---|---|---|
| 700 | 191 | ✅ |
| 600 | 180 | ✅ |
| **800** | **109** | ❌ |
| 500 | 85 | ✅ |
| **850** | **25** | ❌ |
| 400 | 14 | ✅ |
| **750** | **8** | ❌ |
| **900** | **4** | ❌ |
| 300 | 2 | ✅ |
| `bold` / `normal` | 8 | ✅ |

**146 استخدامًا لأوزان 750 / 800 / 850 / 900 غير محمّلة** → المتصفح يولّد *faux bold* (تسميك اصطناعي).

النتيجة العملية:
- حواف مشوّشة، خصوصًا في الحروف العربية (النقاط والوصلات).
- سماكة تختلف بين المتصفحات والأنظمة.
- **`font-weight: 800` و `700` يُصيَّران متطابقين تقريبًا** → التدرّج الهرمي المقصود لا يظهر أصلًا.

هذا خطأ قابل للإصلاح بسطر واحد (إضافة الأوزان للرابط) أو بدمج الأوزان في أربعة (400/500/600/700).

## 7. 🔴 Focus System — أخطر اكتشاف في التحليل

### 7.1 الإخفاء العالمي

في `styles.scss:1850`:

```scss
html:not([data-a11y-focus="default"]):not([data-a11y-focus="high"]) *:focus,
html:not([data-a11y-focus="default"]):not([data-a11y-focus="high"]) *:focus-visible,
html:not([data-a11y-focus="default"]):not([data-a11y-focus="high"]) *:focus-within {
  outline: none !important;
  box-shadow: none !important;
}
```

وفي `src/app/services/accessibility.service.ts:26`:

```ts
focusIndicator: 'off', // Hidden by default; user activates via FAB
```

**النتيجة:** مؤشّر التركيز **مُخفى افتراضيًا في كل التطبيق**، ولا يظهر إلا إذا فتح المستخدم زر إمكانية الوصول العائم واختار "افتراضي" أو "أوضح" يدويًا. والـ `!important` على المحدّد `*` يُبطل أي focus ring يكتبه أي مكوّن.

هذا **فشل مباشر في WCAG 2.1 AA — المعيار 2.4.7 (Focus Visible)**. ولا يُعالَج بإتاحة خيار للمستخدم: المعيار يشترط أن يكون المؤشّر ظاهرًا افتراضيًا لمن يتنقّل بلوحة المفاتيح.

**المفارقة:** التطبيق يملك بنية إمكانية وصول متقدّمة (خمسة تفضيلات، تكبير خط، تباين عالٍ، اختصارات لوحة مفاتيح، اختبارات axe-core) — لكن هذه القاعدة الواحدة تُسقط أهم معيار فيها.

### 7.2 طبقات الإخفاء الأخرى

| الموقع | القاعدة | الأثر |
|---|---|---|
| `panel-style.css:3426` | `.btn:hover, .btn:focus, .btn:active { outline: 0 !important; box-shadow: none; }` | يُلغي التركيز على **970** زرًا |
| `panel-style.css:6637` | `.p-btn-primary:hover, .p-btn-primary:focus { … }` | **focus مطابق تمامًا لـ hover** — لا تمييز إطلاقًا |
| `panel-style.css:2764` | `.form-control:focus { box-shadow: none; border: 1px solid var(--p-primary-color) !important; }` | التركيز = تغيير لون حدّ 1px فقط، بلا ring |
| `deznav-native.component.scss:33` | `.dn-item:hover, .dn-item:focus { color: #000 }` | focus = hover في السايدبار |
| `header.component.scss` | `.notif-bell-btn:hover, &:focus-visible { … outline: none; }` | focus = hover + إلغاء صريح |
| عبر المشروع | **206** إعلان `outline: none / 0` | — |

### 7.3 ما هو موجود ويصلح كأساس للإصلاح

- **202** استخدامًا لـ `:focus-visible` عبر المشروع — النيّة صحيحة.
- `:focus:not(:focus-visible) { outline: none }` — قاعدة **صحيحة تمامًا** (إخفاء التركيز لمستخدم الفأرة فقط). يجب الإبقاء عليها.
- نمط `box-shadow: 0 0 0 3px rgba(brand, .12–.15)` موجود بـ 20 استخدامًا.
- `shared/ui/button` يطبّق `:focus-visible { outline: 2px solid …; outline-offset: 2px }` بشكل سليم.

**الخلاصة:** المكوّنات الحديثة كتبت focus rings صحيحة، لكن القاعدة العالمية تمحوها كلها. الإصلاح هو **قلب المنطق**: التركيز ظاهر افتراضيًا، والـ FAB يزيده وضوحًا فقط (لا يفعّله).

## 11. الخلاصة التشخيصية

المشروع **ليس بلا هوية** — بل يملك هوية واضحة كامنة تحت طبقات من التراكم:

**ما يشكّل الـ Design DNA فعليًا:**

- **اللون:** بنفسجي عميق (`#702EA4`) كعلامة، على محايد بارد (`slate`)، مع بادجات فاتحة للحالات.
- **الخط:** Readex Pro — خيار ممتاز وموحّد لعربية/لاتينية، بمقياس أساسي 13–14px.
- **الشكل:** بطاقات بيضاء، حدود شعرية، نصف قطر 12–14px، ظلال خفيفة جدًا، رفع بسيط عند المرور (`translateY(-1px/-2px)`).
- **التخطيط:** شبكة `auto-fill minmax(280px, 1fr)`، فجوة 16px، حشوة صفحة 24px، عرض أقصى 1200px.
- **الاتجاه:** RTL أصلي بخصائص منطقية.

**ما يفسد هذه الهوية:**

1. ثلاث حِقب لونية متعايشة بلا طبقة توحيد.
2. غياب أي طبقة foundations — 402 ملف SCSS مستقل.
3. قالب مشترى (`panel-style.css`) يفرض قرارات قديمة (`.btn-primary` أسود، `.form-control` بارتفاع 55px) ويقاوَم بـ 406 `!important`.
4. نظام تركيز مُعطَّل عالميًا.
5. اعتماد Tailwind بـ 1 % رغم وجود خارطة طريق تفترض عكس ذلك.

**الطريق:** ليس إعادة تصميم — بل **استخراج الطبقة C، ترقيتها إلى نظام tokens رسمي، ثم سحب الحقبتين A و B إليها تدريجيًا**.
