## 0. المبادئ الحاكمة للتنفيذ

| # | المبدأ |
|---|---|
| P1 | **لا مرحلة "توقّف عندها"** — كل مرحلة تترك التطبيق في حالة صالحة للإصدار. |
| P2 | **التعايش قبل الاستبدال** — النظام الجديد يُحمَّل *بعد* القديم فيعلو عليه بالترتيب، لا بـ `!important`. |
| P3 | **الأثر البصري مُعلن مسبقًا** — كل مرحلة تصرّح: صفر / منخفض / متوسط / عالٍ. |
| P4 | **العزل أولًا** — لا يُلمس شيء قبل وجود نطاق `.ap-admin` يمنع التسرّب إلى الموقع العام. |
| P5 | **مقياس تقدّم واحد** — عدد قيم الـ hex الخام في `views/admin` (اليوم: **448**). يُقاس آليًا في كل PR. |
| P6 | **الترحيل بالفئة لا بالمجلّد** — كل PR يعالج فئة مكوّنات واحدة عبر كل الوحدات. |

## Phase 1 — نظام التركيز (Focus System) ✅ **منجزة**

**الهدف:** حلّ أخطر مشكلة إمكانية وصول في المشروع.

**ما نُفِّذ فعلًا:**

| الملف | التغيير |
|---|---|
| `src/styles/foundations/_focus.css` | **جديد** — النظام كاملًا: `:focus-visible` مرئي افتراضيًا، مستوى `high`، `forced-colors`، حلقة حمراء للأفعال المدمِّرة، حلقة بيضاء للعنصر النشط في السايدبار، أنماط رابط التخطّي |
| `src/styles/foundations/index.css` | جديد |
| `services/accessibility.service.ts` | `FocusIndicatorLevel` صار `'default' \| 'high'` · الافتراضي `'default'` · **`normalizePreferences()` يرحّل `'off'` المحفوظة لدى المستخدمين الحاليين** · `applyToDocument` لم يعد يضع `data-a11y-focus="off"` |
| `accessibility-fab.component.html` | حُذف خيار «إخفاء» (3 خيارات → 2) |
| `styles.scss` | حُذفت كتلة الإخفاء العالمية (62 سطرًا) وكتلة `data-a11y-focus="high"`، واستُبدلتا بمؤشّر إلى ملف الـ foundations |
| `assets/css/panel-style.css` | أُزيل `:focus` من `.btn:hover, .btn:focus, .btn:active` — كان يلغي التركيز على 970 زرًا · `.p-btn-*:focus` → `:focus-visible` (4 قواعد) |
| `deznav-native.component.scss` | فُصل `:focus` عن `:hover` · الانزلاق صار لـ hover فقط · `outline-offset: -3px` لأن حاوية التنقّل تقصّ الفائض |
| `header.component.scss` | حُذفت 5 إعلانات `outline: none` داخل كتل `:focus-visible` |
| `admin.component.html` | أُعيد تفعيل رابط التخطّي (كان معلّقًا) |

**نقطة دقيقة:** لون الحلقة يُختار بحسب **ما خلفها** لا بحسب لون العنصر.
حلقة بحدّ خارجي تقع على خلفية الصفحة البيضاء فتبقى بنفسجية (8.03:1)؛
أما عنصر السايدبار النشط فحلقته داخلية على تعبئة بنفسجية (1:1) → حلقة بيضاء.

**يحلّ:** A-01 · A-02 · A-03 · A-23 — أي **4 من 6** مشاكل حرجة.

**ما تبقّى للتحقّق اليدوي:** التنقّل بـ Tab عبر الصفحات الرئيسية في متصفّح نظيف، والتأكّد من عدم اقتطاع الحلقة داخل حاويات `overflow: hidden` أخرى.

### تفاصيل التخطيط الأصلية للمرحلة

| البند | التفصيل |
|---|---|
| **الأثر البصري** | **منخفض** — إضافة فقط (ظهور ring عند التنقّل بلوحة المفاتيح)، بلا أي تغيير في التخطيط أو الألوان |
| **الملفات** | `services/accessibility.service.ts` · `styles.scss` (بلوك التركيز) · `panel-style.css` (سطر واحد) · `deznav-native.component.scss` · `header.component.scss` · `src/styles/foundations/_focus.css` (جديد) |
| **المكوّنات** | كل عنصر تفاعلي (استفادة) |
| **يحلّ** | A-01, A-02, A-03, A-23 |

**المهامّ:**

1. `focusIndicator: 'off'` → `'default'` في `accessibility.service.ts:26`.
2. إعادة كتابة بلوك التركيز في `styles.scss`: التركيز ظاهر افتراضيًا، والـ FAB يقدّم `default` / `high` فقط — **حذف الخيار `off`**.
3. الإبقاء على `:focus:not(:focus-visible) { outline: none }`.
4. حذف `:focus` من `.btn:hover, .btn:focus, .btn:active` في `panel-style.css:3426`.
5. فصل `:focus-visible` عن `:hover` في `.p-btn-*`, `.dn-item`, `.notif-bell-btn`.
6. إنشاء `_focus.css` بقاعدة واحدة تستخدم `--ap-focus-ring`.
7. إعادة تفعيل رابط التخطّي في `admin.component.html` + أنماطه.

**المخاطر:**

| الخطور | التخفيف |
|---|---|
| ظهور ring على عناصر لم تكن تُظهره → إحساس بـ"ضجيج بصري" | `:focus-visible` وحده — لا يظهر لمستخدم الفأرة إطلاقًا |
| تعارض مع أنماط `outline` محلية (206 إعلان `outline:none`) | الطبقة الجديدة تُحمَّل بعدها؛ المتبقّي يُعالَج فرديًا مع ترحيل كل مكوّن |
| مستخدمون اعتادوا غياب الـ ring | تغيير مقصود ومطلوب معياريًا |

**التحقّق:** تنقّل بـ Tab في متصفّح نظيف عبر 10 صفحات — كل محطّة مرئية · اختبار تباين الـ ring نفسه (3:1 مقابل الخلفية المجاورة) · لقطات Playwright تُظهر صفر فرق في حالة الراحة.

| **المكوّنات** | كل الحقول |

**المهامّ:**

2. إضافة `role="alert"` + `aria-live="polite"` لرسائل الأخطاء الحالية **في مكانها** (بلا نقلها بعد).
3. إضافة `aria-invalid` مربوطًا بحالة التحقّق.
4. `aria-label` على أزرار الأيقونات + `aria-hidden="true"` على كل `<i>` زخرفية.
5. `aria-required` على الحقول الإلزامية.

**المخاطر:**

| الخطر | التخفيف |
|---|---|
| حجم التغيير (150 ملفًا) | تقسيم على PRs حسب الوحدة؛ صفر أثر بصري يجعل المراجعة سريعة |

| `aria-live` مفرط النشاط → ثرثرة | `polite` لا `assertive`، ورسالة واحدة لكل حقل |

**التحقّق:** `npm run test:a11y` بعد إضافة صفحات Admin · فحص يدوي بـ NVDA على ثلاثة نماذج · صفر فرق في لقطات Playwright.

## Phase 4 — الطباعة والمسافات

| البند | التفصيل |
|---|---|
| **الأثر البصري** | **متوسط** |
| **الملفات** | `index.html` · كل SCSS في `views/admin` |
| **يحلّ** | A-16, A-17, A-27 |

**المهامّ:**

1. **حصر الأوزان في الأربعة المحمّلة** — استبدال 146 استخدامًا لـ 750/800/850/900 بـ 600/700. *(أثر: إيجابي — يزيل faux-bold)*
2. حذف إعلانات `Cairo`/`Tajawal`/`Droid Arabic Kufi`/`Almarai` غير المحمّلة (49 إعلانًا لا تنتج شيئًا).
3. تطبيع 90 حجم خط على السلّم العشري + التحويل إلى `rem`.
4. ربط `line-height` بالحجم عبر ستايلات النص الدلالية.
5. تطبيع المسافات على `--ap-space-*` بالبكسل — بدءًا بالـ 120 قيمة rem الكسرية.
6. **إصلاح الـ 138 كلاس `ms-*`/`me-*` الميت** — استبداله بـ `mr-*`/`ml-*` الصحيح أو بخصائص منطقية. *(أثر: إيجابي — يعيد مسافات مفقودة)*

**المخاطر:**

| الخطر | التخفيف |
|---|---|
| تحويل px→rem يغيّر الأحجام مع تكبير الخط | مقصود — هذا هو الإصلاح؛ اختبار عند كل مستوى تكبير |
| إصلاح `ms-*`/`me-*` **يُظهر** مسافات لم تكن موجودة | مقصود، لكن يحتاج مراجعة بصرية — 138 موضعًا |
| دمج 90 حجمًا في 10 يغيّر كثافة الشاشات | البدء بالفروق ≤ 0.5px (لا أثر)، ثم التدرّج |

**التحقّق:** لقطات عند مستويات التكبير الخمسة · قياس عدد الأحجام المميزة (هدف: 10).
