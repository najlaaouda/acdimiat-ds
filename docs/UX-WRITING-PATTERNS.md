> **الغرض:** قوالب جاهزة لإعادة الاستخدام. عند كتابة أي نصّ جديد، **ابحث هنا أولًا**.
> **مصدر الأنماط:** مستخرَجة من النص القائم في Admin Panel — لا يوجد نمط مخترَع.

## 0. القواعد الحاكمة — تنطبق على كل نمط أدناه

| # | القاعدة |
|---|---|
| 1 | **المصطلح قبل الصياغة.** راجع `UX-WRITING-TAXONOMY.md` قبل كتابة الكلمة الأولى. |
| 2 | **أقصر نصّ يؤدّي المعنى يفوز.** إذا حُذفت كلمة ولم يتغيّر الفهم، تُحذف. |
| 3 | **لا نصّ بلا وظيفة.** إن لم يغيّر النصّ ما يفهمه المستخدم أو ما يفعله، يُحذف. |
| 4 | **لا نقطة في:** التسميات · الأزرار · العناوين · الحالات · عناوين الأعمدة · الحالات الفارغة القصيرة. |
| 5 | **نقطة في:** الوصف المكوَّن من جملة كاملة · النصّ المساعد · وصف الحوار. |
| 6 | **الترقيم عربي:** `،` · `؛` · `؟` — ملتصقة بما قبلها، بمسافة بعدها. `…` حرف واحد. |
| 7 | **لا إيموجي · لا علامة تعجّب · لا مبالغة.** |
| 8 | **الأرقام غربية** `0-9`. |
| 9 | **CTA بصيغة المصدر** (`حفظ`). **التعليمات بصيغة الأمر** (`أضف`). **`قم بـ` ممنوعة.** |
| 10 | **لا لوم للمستخدم** ولا افتراض أن العطل عنده. |

## 1. Page Title Pattern

| نوع الصفحة | الصيغة | مثال | مصدر النمط |
|---|---|---|---|
| **قائمة** | اسم الجمع معرَّفًا | `الدورات` · `المستخدمون` · `الكوبونات` | السايدبار (47 عنصرًا متّسقًا) |
| **تفاصيل** | اسم العنصر نفسه | `دورة التسويق الرقمي` | `breadcrumb.ts` `SESSION:_product_title` |
| **إنشاء** | `إنشاء [المفرد النكرة]` | `إنشاء دورة` · `إنشاء مقال` | `إنشاء نقاش` · `إنشاء موسوعة` |
| **تعديل** | `تعديل [المفرد المعرَّف]` | `تعديل الدورة` · `تعديل التصنيف` | `تعديل التصنيف` · `تعديل الوسم` |
| **إعدادات** | `إعدادات [النطاق]` | `إعدادات الأكاديمية` · `إعدادات المدونة` | السايدبار |
| **تبويب داخل تفاصيل** | اسم مجرَّد | `البيانات` · `التسعير` · `الطلاب` | `breadcrumb.ts` |

**القاعدة:** عنوان الصفحة **يطابق حرفيًّا** اسم عنصر السايدبار أو الـ breadcrumb الذي قاد إليها. لا مرادفات.

**❌ مرفوض:**

```text
❌ إدارة الدورات        ← «إدارة» حشو، الصفحة كلها إدارة
❌ قائمة المستخدمين      ← «قائمة» حشو
❌ صفحة الإعدادات        ← «صفحة» حشو
❌ الأرقام السريعة        ← لا يطابق «تقارير وإحصائيات» في السايدبار
```

## 2. Button Patterns

### 2.1 الصيغ

| الدور | الصيغة | مثال |
|---|---|---|
| **Primary — إجراء أساسي** | `فعل` مصدرًا، أو `فعل + مفعول` عند وجود أكثر من هدف على الشاشة | `حفظ` · `نشر` · `حذف القسم` · `إضافة مستخدم` |
| **Secondary — بديل** | `فعل` مصدرًا | `معاينة` · `تصدير Excel` |
| **Tertiary / نصّي** | `فعل` أو `فعل + وجهة` | `عرض التفاصيل` · `الرجوع إلى الدورات` |
| **إلغاء** | `إلغاء` — بلا استثناء | `إلغاء` |
| **إغلاق حوار معلوماتي** | `إغلاق` | `إغلاق` |
| **موافقة على معلومة** | `موافق` | `موافق` |

### 2.2 متى يُضاف المفعول؟

```text
شاشة فيها زرّ حفظ واحد          →  حفظ
شاشة فيها حفظ للمسودّة والنشر    →  حفظ كمسودّة  ·  نشر
قائمة فيها حذف لعناصر مختلفة     →  حذف القسم  ·  حذف الصورة  ·  حذف الفيديو
```

### 2.3 حالة التحميل داخل الزرّ

الزرّ **لا يبدّل تسميته**. يُعطَّل ويُعرض دوّار بجانب التسمية.

```text
✅  [⟳] حفظ            ← معطّل، التسمية ثابتة
❌  جاري الحفظ...       ← تغيّر عرض الزرّ وقفز التخطيط
```

**استثناء:** العمليات التي تتجاوز 5 ثوانٍ ولا مؤشّر آخر لها ← `جارٍ الإنشاء…`.

### 2.4 ممنوع في الأزرار

```text
❌ اضغط هنا · انقر هنا · اضغط على الزر
❌ «الآن» و«الان»            ← ترقية الباقة الان → ترقية الباقة
❌ إيموجي                     ← ✨ إنشاء المقال → إنشاء المقال
❌ نقطة في النهاية
❌ جملة كاملة                 ← «قم بإضافة خطة تسعير» → «إضافة خطة تسعير»
```

## 3. Modal Patterns

### 3.1 البنية الموحَّدة

```text
Title              سؤال أو اسم إجراء — سطر واحد، بلا نقطة
Description        ما سيحدث فعلًا — جملة أو جملتان بنقطة، تُحذف إن لم تُضِف معلومة
Primary action     الفعل نفسه المذكور في العنوان
Secondary action   إلغاء
```

### 3.2 القوالب الأربعة

النظام يملك بنية `ConfirmDialogKind` جاهزة في `shared/components/confirm-dialog/`. الأنماط التالية تُملأ فيها:

#### Confirmation (general)

```text
Title        هل تريد [الفعل]؟
Description  (يُحذف إن كان الفعل واضحًا ومرتدًّا)
Primary      [الفعل]
Secondary    إلغاء

مثال:
    هل تريد نشر هذه الصفحة؟
    ستصبح الصفحة مرئية لجميع الزوار.
    [نشر]  [إلغاء]
```

#### Delete (delete-content)

```text
Title        حذف «[اسم العنصر]»؟          ← إن كان مسمًّى ومختارًا من قائمة
             حذف هذا [النوع]؟             ← إن كان بلا اسم أو داخل صفحته
Description  ما يُفقد + هل يمكن التراجع. تُحذف إن كان الأثر بديهيًّا.
Primary      حذف
Secondary    إلغاء

مثال:
    حذف «دورة التسويق الرقمي»؟
    سيفقد 42 طالبًا الوصول إلى محتوى الدورة. لا يمكن التراجع.
    [حذف]  [إلغاء]
```

**اسم العنصر يُوضع بين علامتَي تنصيص عربيتين `«…»`** — النمط المستخدَم أصلًا في `اضغط «إضافة سؤال» لبدء بناء الاختبار`.

#### Warning (publish-change / access-lock)

```text
Title        [الفعل] [العنصر]؟
Description  [الخطر]. [ما يمكن للمستخدم فعله].
Primary      [الفعل]
Secondary    إلغاء

مثال:
    إخفاء هذه الدورة؟
    سيتوقف وصول الطلاب المسجَّلين حتى تُعيد نشرها.
    [إخفاء]  [إلغاء]
```

#### Information

```text
Title        [الموضوع]
Description  المعلومة كاملة.
Primary      موافق
Secondary    (لا يوجد)
```

### 3.3 حوار التعديل غير المحفوظ

```text
حفظ التعديلات؟
ستفقد التعديلات الحالية إذا لم تحفظها.
[حفظ]  [إلغاء]
```

النصّ الوصفي موجود أصلًا كثابت `UNSAVED_CHANGES_LOST_WARNING` — **يُستخدم ولا يُعاد كتابته**.

### 3.4 ممنوع

```text
❌ «هل أنت متأكد؟» وحدها                ← لا تقول ماذا سيحدث
❌ «عدم الحفظ» · «عدم المتابعة»           ← الزرّ الثانوي هو «إلغاء»
❌ «نعم» / «لا»                          ← الأزرار تسمّي الإجراء
❌ عنوان بـ 20 كلمة يخلط التحذير بالسؤال
❌ مسافة قبل «؟»
```

## 4. Form Patterns

### 4.1 Label

```text
اسم مجرَّد معرَّف بأل · بلا نقطتين · بلا نقطة · بلا «الرجاء»

✅ الاسم · البريد الإلكتروني · تاريخ البدء · سعر الدورة
❌ الحالة: · اسم الدورة؟ · أدخل الاسم · الاسم *
```

**الإلزام — تُعلَّم الأقلّية لا الأكثرية.** ثلاث حالات، وقاعدة واحدة تحكمها: ما لا استثناء له لا يحتاج تمييزًا.

| النموذج | ما يُكتب |
|---|---|
| **كل** الحقول مطلوبة | سطر واحد تحت عنوان النموذج: `جميع الحقول أدناه مطلوب إدخالها` — وصفر تعليم على الحقول |
| حقل واحد مطلوب والباقي اختياري | `(مطلوب إدخاله)` على ذلك الحقل وحده |
| الأغلب مطلوب وواحد أو اثنان اختياريان | `(اختياري)` على الاختياري وحده. النمط موجود أصلًا: `الوسم الافتراضي (احتياطي) (اختياري)` |

موضع الجملة تحت عنوان النموذج نفسه — تحت «إضافة عميل» مثلًا، لا في أعلى الصفحة: النموذج هو ما تصفه، وصفحةٌ فيها نموذجان يكذب فيها العنوان الأعلى.

⛔ **لا نجمة `*`** — رمز يحتاج مفتاحًا يشرحه، وقارئ الشاشة يقرؤها «نجمة» أو يتجاهلها. الكلمة مكتوبة.

ينفّذ `<ap-field>` الحالتين الثانية والثالثة: `[required]` → `(مطلوب إدخاله)`، و`[showOptional]` → `(اختياري)`. والحالة الأولى نصّ تكتبه الشاشة تحت عنوانها.

### 4.2 Placeholder

**القاعدة: مثال، لا تكرار للتسمية، لا تعليمات.**

```text
✅  Label: سعر الدورة        Placeholder: مثال: 49.00
✅  Label: اسم الحملة         Placeholder: مثال: حملة إطلاق الدورة
✅  Label: التصنيف            Placeholder: مثال: التسويق الرقمي

❌  Label: اسم الخطة          Placeholder: اسم الخطة          ← تكرار
❌  Label: الموضوع            Placeholder: اكتب الموضوع الرئيسي للمقال...  ← تعليمات
```

**متى يُترك فارغًا؟** حين لا يوجد مثال مفيد (خانة اختيار، قائمة منسدلة، تاريخ).

**حقل البحث — استثناء:**

```text
البحث بـ[الحقول التي يطابقها الترشيح فعلًا] [الكيان]

✅ البحث باسم أو بريد العميل
✅ البحث ببريد العميل
✅ البحث برقم التذكرة أو اسم الطالب
✅ البحث باسم الكوبون أو كوده
❌ بحث... · بـحــث · البحث
```

### 4.3 Helper text

```text
يظهر تحت الحقل · جملة واحدة · بنقطة · يجيب على واحد فقط مما يلي:
    - ما القيد التقني؟        «يفضل ألا يتجاوز 60 حرفًا.»
    - ما صيغة الإدخال؟         «أرقام فقط بدون رمز العملة.»
    - ما أثر هذا الخيار؟       «عند التفعيل، تُعرض الأسعار بعملة بلد الزائر.»
    - ما نطاق الأثر؟           «يُستخدم فقط للصفحات التي لا تملك وسمًا خاصًّا بها.»

❌ لا يكرّر التسمية
❌ لا يشرح ما هو الحقل («هذا الحقل للاسم»)
❌ لا نبرة تحفيزية ولا إيموجي
```

### 4.4 Validation

```text
[اسم الحقل] مطلوب                     ← الحقل فارغ
[اسم الحقل] غير صحيح                  ← الصيغة خاطئة
[القيد بصيغة إيجابية]                  ← القيمة خارج النطاق

✅ البريد الإلكتروني مطلوب
✅ البريد الإلكتروني غير صحيح
✅ أقل عدد طلبات هو 1
✅ يُسمح بالحروف والأرقام والرموز: ~ _ -
✅ الاسم بحد أقصى 35 حرفًا

❌ يرجى تعبئة الحقل            ← لا يسمّي الحقل
❌ يجب اضافة كود                ← نبرة آمرة + إملاء
❌ قم بإضافة بيانات صحيحه       ← لا يسمّي الخطأ + إملاء
❌ هذا الحقل مطلوب              ← احتياطي فقط، حين يتعذّر معرفة اسم الحقل
```

**رسالة النموذج كاملًا عند الإرسال:** `راجع الحقول المميّزة بالأحمر` — لا `يرجى ملء الحقول المطلوبة` (لا تدلّ على مكانها).

## 5. Error Patterns

### 5.1 الهيكل

```text
Problem   →  تعذّر [الفعل]
Reason    →  [السبب]              ← فقط إن كان يغيّر ما يفعله المستخدم
Action    →  [الإجراء المتاح]
```

### 5.2 القوالب

| الحالة | النصّ |
|---|---|
| فشل عملية عابرة | `تعذّر [الفعل]. حاول مرة أخرى.` |
| فشل بسبب قيد الباقة | `تعذّر [الفعل] — [القيد]. رقِّ باقتك للمتابعة.` |
| فشل بسبب صلاحية | `ليس لديك صلاحية [الفعل].` |
| فشل جزئي | `تم [ما نجح] لكن تعذّر [ما فشل] — [الإجراء].` |
| فشل بسبب بيانات المستخدم | `[اسم الحقل] غير صحيح.` |
| فشل غير معروف — **الملاذ الأخير فقط** | `تعذّر إتمام العملية. حاول مرة أخرى.` |

### 5.3 أمثلة كاملة

```text
✅ تعذّر حفظ التغييرات. حاول مرة أخرى.
✅ تعذّر رفع الصورة — الحجم يتجاوز 2MB. اختر صورة أصغر.
✅ تم الحفظ لكن تعذّر تحديث القائمة — أغلق النافذة وأعد فتحها.
✅ تجاوزت الحد الشهري لإرسال الرسائل. رقِّ باقتك للمتابعة.

❌ حدث خطأ غير متوقع / يرجى التحقق من الاتصال وإعادة المحاولة
❌ خطأ
❌ Something went wrong
❌ حدث خطأ, لم نستطع العثور على صفحاتك, يرجى التحقق من الاتصال وإعادة المحاولة
```

### 5.4 القواعد

```text
- الفعل الموحَّد للفشل: تعذّر   (لا «فشل» ولا «لم يتم» ولا «لم نستطع»)
- لا تلوم المستخدم ولا اتصاله ما لم يكن الخطأ خطأ شبكة مؤكَّدًا
- لا تعرض كود خطأ ولا اسم API ولا رسالة الخادم الخام
- لا تعتذر
- الخطأ لا يحجب الواجهة إلا إذا تطلّب قرارًا من المستخدم
```

## 6. Empty State Patterns

### 6.1 البنية

```text
Title              لا [يوجد/توجد] [الكيان] بعد        ← ما الحالة
Description        [لماذا تهمّ / ما يمكن فعله]         ← اختياري
Primary Action     [الفعل الذي ينهي الحالة]           ← عند وجود إجراء
Secondary Action   (نادر — مثل «تعرّف على المزيد»)
```

**⚠️ التذكير والتأنيث:** جمع غير العاقل يُعامَل معاملة المؤنّث المفرد → **`لا توجد`**.
`لا توجد كوبونات` · `لا توجد اشتراكات` · `لا توجد ملفات`
**`لا يوجد`** فقط مع المفرد أو جمع العاقل المذكّر: `لا يوجد اشتراك نشط` · `لا يوجد مسوّقون`.

### 6.2 الأنواع الستّة

#### أ) First-use — لا بيانات ولم يُنشأ شيء بعد

```text
لا توجد [الكيان] بعد
[ما تكسبه بإنشاء الأول].
[إنشاء [الكيان]]

مثال (من المنتج):
    لا توجد إصدارات بعد
    أضف أول إصدار منافس لبدء الاختبار.
    [إضافة إصدار]
```

#### ب) No data — لا بيانات ولا إجراء مباشر

```text
لا توجد [الكيان]

مثال:
    لا توجد مبيعات هذا الشهر
```

بلا وصف وبلا زرّ. الغياب هنا معلومة، لا مشكلة.

#### ج) No search results

```text
لا توجد نتائج مطابقة لبحثك
يرجى التحقق من الأحرف وإعادة المحاولة.
[مسح البحث]
```

نصّ ثابت لا يردّد الاستعلام: هو مكتوب في الحقل فوق الجدول أصلًا،
والمطلوب هنا التصحيح لا التأكيد.

#### د) Filtered empty

```text
لا توجد [الكيان] مطابقة للتصفية
[مسح التصفية]
```

**الفرق عن (ج):** المستخدم صفّى ولم يبحث — الإجراء هو مسح التصفية لا تغيير الكلمات.

#### هـ) Permission restricted

```text
ليس لديك صلاحية عرض [الكيان]
تواصل مع مالك الأكاديمية لطلب الصلاحية.
```

بلا زرّ أساسي — لا شيء يستطيع المستخدم فعله بنفسه.

#### و) Feature unavailable — قيد الباقة

```text
[اسم الميزة] متاحة في باقة [الاسم] وما فوقها
[ترقية الباقة]
```

النمط الحالي `متاح على باقة بلاتينيوم وما فوق` (6 مواضع) صحيح المضمون — يُوحَّد لفظًا فقط.

### 6.3 ممنوع

```text
❌ لا يوجد كوبونات               ← خطأ نحوي
❌ لا يوجد بيانات لعرضها          ← «لعرضها» حشو
❌ لا توجد نتائج لعرضها حالياً.    ← حشو مزدوج
❌ لا توجد بيانات في هذا الوقت    ← «في هذا الوقت» بلا معنى
❌ قريباً...                      ← ليست حالة فارغة؛ استخدم نمط (و) أو أخفِ الميزة
```

## 7. Success Patterns

### 7.1 الصيغة

```text
تم [الفعل]

✅ تم حفظ التغييرات
✅ تم نسخ الرابط
✅ تم إرسال الرسالة
✅ تم تفعيل الكوبون
```

### 7.2 القرار الأول — هل نعرض رسالة أصلًا؟

```text
هل يرى المستخدم النتيجة بنفسه؟
    ├─ نعم  →  لا رسالة
    │          (الصفّ اختفى · المفتاح انتقل · العناصر أُعيد ترتيبها ·
    │           انتقلنا لصفحة العنصر الجديد)
    └─ لا   →  Toast: تم [الفعل]
               (حفظ نموذج بقي مكانه · نسخ للحافظة ·
                عملية خلفية طويلة · إرسال بريد)
```

### 7.3 ممنوع

```text
❌ «بنجاح»                        ← «تم» تفيد النجاح
❌ «تمت العملية»                  ← لا تسمّي شيئًا
❌ علامة تعجّب
❌ عرض معرّف تقني: «تم الإنشاء! ID: 4821»
❌ رسالة نجاح لعملية نتيجتها مرئية
```

## 8. Loading Patterns

```text
جارٍ [المصدر]…

جارٍ التحميل…      جارٍ الحفظ…       جارٍ الإنشاء…
جارٍ الحذف…        جارٍ الإرسال…     جارٍ الرفع…
جارٍ التصدير…
```

**متى يُكتب النصّ؟**

| المدّة | الوسيلة |
|---|---|
| < 2 ث | دوّار داخل الزرّ · بلا نصّ |
| 2–5 ث | Skeleton أو دوّار · بلا نصّ |
| 5–15 ث | `جارٍ [المصدر]…` |
| > 15 ث | `جارٍ [المصدر]…` + توقّع: `قد يستغرق هذا حتى دقيقة. لا تغلق النافذة.` |

**تحميل أول للقائمة:** Skeleton بلا نصّ — لا `جارٍ التحميل…`.

## 9. Notification Patterns

| النوع | الصيغة | مثال |

| **Success** | `تم [الفعل]` | `تم حفظ التغييرات` |

## 10. Status Patterns

الحالة **اسم أو صفة · بلا فعل · بلا جملة · بلا نقطة**.

```text
✅ مفعّل · غير مفعّل · منشور · مخفي · مسودّة
✅ قيد الانتظار · قيد المراجعة · قيد المعالجة · مكتمل · مرفوض · ملغى · فاشل
✅ ساري · منتهٍ · لم يبدأ بعد

❌ تم الحل        →  محلولة
❌ تم التفعيل     →  مفعّل
❌ في الانتظار    →  قيد الانتظار
❌ نشط / فعال     →  مفعّل
```

الجدول الكامل بمحاوره الأربعة وألوانه الدلالية في [`UX-WRITING-TAXONOMY.md`](./UX-WRITING-TAXONOMY.md) §5.

## 14. Onboarding Patterns

النمط الوحيد المرصود يعمل جيدًا (`get-started`) ويُبنى عليه:

```text
عنوان الخطوة      [الفعل] [الهدف]         «قم بنشر أكاديميتك» → «انشر أكاديميتك»
وصف الخطوة        جملة واحدة: ماذا وما فائدته.
زرّ الخطوة         [الفعل]
مؤشّر التقدّم      أتممت [X]% من إعداد أكاديميتك
```

`لقد أتممت {{ progress }}% من الخطوات المطلوبة لتكون دورتك مكتملة` ← **`أتممت {{ progress }}% من إعداد الدورة`**.

## 15. UX Writing Decision Framework

**قبل كتابة أي نصّ جديد، أجب على العشرة بالترتيب. توقّف عند أول «لا».**

```text
 1. ما هدف المستخدم في هذه اللحظة؟
      → إن لم يكن واضحًا، لا تكتب. افهم الشاشة أولًا.

 2. ما الذي يحتاج المستخدم إلى فهمه ليتخذ الخطوة التالية؟
      → هذا وحده هو المحتوى. الباقي حشو.

 3. هل هذا النصّ ضروري؟
      → إن حُذف ولم يتغيّر شيء، احذفه.

 4. هل يمكن تقليل عدد الكلمات دون فقد المعنى؟
      → «تم القيام بعملية حفظ البيانات بنجاح» → «تم حفظ التغييرات»

 5. هل الـ Action واضح؟
      → الزرّ يقول ماذا سيحدث، لا كيف يُنقر.

 6. هل النصّ متوافق مع المصطلحات المعتمَدة؟
      → راجع UX-WRITING-TAXONOMY.md. طالب؟ عميل؟ مستخدم؟ الشاشة تحدّد.

 7. هل يوجد Pattern سابق في هذه الوثيقة يغطّي الحالة؟
      → إن وُجد، استخدمه حرفيًّا. لا تُنشئ صيغة موازية.

 8. هل الرسالة مناسبة للسياق والوسيط؟
      → Toast أم Inline أم Modal؟ راجع §9.

 9. هل غطّيت الحالات الأربع: success · error · empty · loading؟
      → الميزة ليست مكتملة بثلاث منها.

10. هل يُفهم النصّ دون شرح إضافي، ودون معرفة سابقة بالنظام؟
      → إن احتاج شرحًا، أعد كتابته لا تشرحه.
```

### 15.1 حين لا يوجد Pattern

```text
1. ابحث عن أقرب نمط — 80 % من الحالات الجديدة تفريعة من نمط قائم.
2. إن لم يوجد، ابحث في المنتج عن نصّ لحالة مشابهة (grep) واستخرج منه.
3. إن لم يوجد، اكتب النصّ ملتزمًا بالقواعد العشر في §0،
   ثم **أعلن صراحةً أن هذا نمط جديد** واعرضه للاعتماد.

❌ لا يُضاف نمط إلى هذه الوثيقة تلقائيًّا. الإضافة قرار، لا أثر جانبي.
```

## 16. Feature Completion Checklist

الميزة الجديدة **ليست مكتملة** قبل اجتياز السبعة:

```text
☐ Visual consistency        Tokens فقط — لا لون ولا مقاس جديد
☐ Component consistency     مكوّنات قائمة — لا مكوّن جديد بلا قرار
☐ Copy consistency          كل نصّ من نمط في هذه الوثيقة
☐ Terminology consistency   كل مصطلح من UX-WRITING-TAXONOMY.md
☐ State coverage            success · error · empty · loading · permission
☐ Accessibility             aria-label عربي · تركيز مرئي · تباين
☐ RTL                       ترقيم عربي · dir="ltr" للبريد والروابط والأكواد
```
