# نظام تصميم أكاديميات

<div dir="rtl">

مصدر نظام تصميم لوحة تحكّم **أكاديميات**، مستخرَجًا من التطبيق في تطبيق Angular مستقلّ
يعمل وحده: طبقات التوكنات، مكتبة المكوّنات، وموقع التوثيق الذي يعرضها.

**36** صفحة توثيق · **42** عرضًا حيًّا · **21** مكوّنًا · **892** توكنًا · عربي RTL بالكامل.

---

## التشغيل

```bash
npm install
npm start          # http://localhost:4200 → يعيد التوجيه إلى /design-system
npm run build      # بناء إنتاجي إلى dist/
npm run lint:a11y  # فاحص إتاحة الوصول للقوالب
```

> يُركَّب الموقع على `/design-system` وليس على الجذر عن قصد: كل روابطه الداخلية
> مبنيّة من `DOCS_ROOT` في `core/docs-nav.config.ts`، فتركيبه على المسار نفسه الذي
> تستعمله اللوحة يجعل أي رابط منسوخ من هنا يعمل هناك، والعكس.

## طبقات التوكنات

ثلاث طبقات، الاتجاه فيها واحد لا يُختصر — مكوّن يقرأ من `primitive` مباشرةً يكسر
إعادة التلوين:

| الطبقة | النطاق | المحتوى |
|---|---|---|
| `_primitives.css` | `:root` | مقاييس خام بلا معنى — سلالم الألوان والمسافات والخطوط |
| `_semantic.css` | `.ap-admin, .ap-docs` | الأسطح والنصوص والحدود والأفعال والحالات والتركيز |
| `_components.css` | `.ap-admin, .ap-docs` | قيم لكل مكوّن ولكل حالة |

نطاق الطبقتين الأخيرتين مقصود: هوية اللوحة البنفسجية يجب ألّا تتسرّب إلى موقع
الأكاديمية العام، الذي يحمل هوية خضراء قابلة للتخصيص لكل أكاديمية.

**قواعد ثابتة:** أوزان الخطّ 400/500/600/700 فقط (وهي الأوزان المحمَّلة من
Readex Pro، وغيرها يُرسَم faux-bold ويشوّه الحرف العربي) · مقياس الأحجام
10/12/14/16/18/20/24/28/32 بكسل · المسافات بالبكسل لا بالـ`rem`، لأن التطبيق
يوسّع `html { font-size }` لإتاحة الوصول و`rem` كان سيضخّم التخطيط مع النص ·
`letter-spacing` صفر، لأن القيمة الموجبة تكسر وصل الحروف العربية.

## مكتبة المكوّنات

المكوّنات **محدِّدات سمات على عناصر أصيلة** (`<button apButton>` لا `<ap-button>`):
عنصر غلاف يكسر `type="submit"` داخل النموذج، ويفرض تمرير `disabled` يدويًّا،
ويشطر مساحة اللمس.

ستّة استثناءات مقصودة، كلّها حاويات أو بدائل لا عناصر تحكّم:
`<ap-select>` (لا يوجد عنصر أصيل يُحسَّن — قائمة `<select>` يرسمها نظام التشغيل
ولا تقبل CSS أصلًا) · `<ap-modal>` · `<ap-tab-nav>` · `<ap-breadcrumbs>` ·
`<ap-search-field>` · `<ap-pagination>` · `<ap-illustration>`.

كل عنصر تحكّم في النماذج يحتاج حاويته، وهذا **مفروض بنيويًّا لا بالاتفاق**:
الموجّه لا يملك ورقة أنماط خاصّة، فأنماط `[apInput]`/`[apSelect]` تعيش في
`ap-field.component.scss` — استعمال العنصر يعني استيراد حاويته، والحاوية هي ما
يولّد `id` و`for` و`aria-describedby`، فلا يوجد مسار ينتج عنصرًا بلا اسم.

## موقع التوثيق

مُوجَّه بالبيانات: إضافة صفحة = **تعديلان** — ملفّ
`registry/<category>/<slug>.doc.ts` يُصدِّر `DocEntry`، وسطر في `registry/index.ts`.
التنقّل وفهرس التصنيف والإحصاءات وروابط السابق/التالي وجدول المحتويات كلّها
تُشتقّ من ذلك.

قاعدتان تمنعانه من الانحراف عن الكود:

- **قسم `tokens` لا يكتب قيمة أبدًا.** يسرد الأسماء فقط، ويقرأ
  `DocTokensComponent` القيم الحقيقية بـ`getComputedStyle` وقت العرض. القراءة
  تكون من عنصر **داخل** `.ap-docs` لا من `documentElement` — الطبقتان الدلالية
  ومكوّنات مقصورتان على النطاق، والجذر يعيد نصًّا فارغًا بصمت.
- **ثابت المصدر المُصدَّر هو قالب العرض نفسه.** يُصدِّر
  `demos/**/*.demo.ts` الثابت `X_SOURCE` ويستعمله `template:`، فلوحة الكود
  وما يُعرَض نصّ واحد لا نسختان.

العروض ومصفوفات الحالات تُعرَض داخل مسارح `ViewEncapsulation.ShadowDom`، وإلّا
لصبغها التتالي العام ووثّقنا التلوّث بدل المكوّن.

## الاختلاف عن اللوحة الأصلية

| | اللوحة | هذا المستودع |
|---|---|---|
| الأوراق العامة | `bootstrap.css` · `panel-style.css` · `rtl.css` · سمة Material | لا شيء — `styles.scss` أساس أدنى فقط |
| نقطة التركيب | مسار داخل التطبيق الكامل | تطبيق مستقلّ |
| `audit:tokens` | يفحص شاشات اللوحة بحثًا عن القيم الخام | غير مضمَّن — يفحص التطبيق لا النظام |

الفارق الأول هو الأهمّ عند المقارنة: النظام في اللوحة يعمل داخل تتالٍ عامّ لا
عزل فيه، وكثير من قواعده الدفاعية موجودة لهذا السبب وحده. غيابها هنا يجعل
المعاينة أنظف من الواقع — **تحقّق من التركيز وحالات الخطأ على شاشة حقيقية في
اللوحة، لا في المعاينة**.
